What happens when an attacker writes instructions into an SSH username?

My lab's AI triage agent reads attacker-controlled alert fields. So I attacked it. The first version didn't pass. Here is the pipeline, and where it is defended.

  1. Attack

    Kali + Hydra

    SSH brute force against an Ubuntu target, ending in a successful login.

  2. Detection

    Wazuh rule 100101

    Five or more failed SSH logins, then a success from the same IP within 120 seconds. Fires at level 12.

  3. Untrusted input

    Crafted alerts

    Adversarial alert samples hide instructions in the username, source IP and log message fields.

  4. Model reads it

    Local LLM agent

    qwen3:4b on Ollama, offline. It advises only: it cannot block IPs, disable accounts or change severity.

  5. Contained

    Python guardrails

    Severity computed in code. An injection tripwire and a recommendation sanitiser catch what the model lets through.

The injection never downgraded a level-12 alert. My first test run against three OWASP LLM risk categories still exposed two gaps: a schema-manipulation attempt went undetected, and a prompt-extraction attempt leaked into a recommendation. Both are fixed and covered by regression tests in GitHub Actions. Read the write-up.

The SOC homelab

A segmented attack-and-detect environment I built to reproduce real techniques, check whether my detections actually fire, and write up the gaps honestly.

  • Proxmox host with segmented security zones routed through OPNsense, keeping attack tooling separate from monitored targets.
  • Suricata and Wazuh caught the same Hydra brute force from two angles: the network and the host.
  • Custom rule 100101 was validated against real log lines with wazuh-logtest before it was trusted.
  • Findings are labelled observed or detected. A technique counts as covered only when an alert fires, not when traffic merely shows up in a log.
  • The local LLM triage agent runs offline, at zero marginal cost, with no data leaving the network. It is built for under-resourced SOCs.
